# S3 operations and boto3

Return to the [guide index](index.md). See [Triggers and events](triggers.md) for trigger references.

Every `s3` command takes a trigger reference (name or ID) and works on that trigger's bucket. Each command exchanges your token for short-lived, operation-scoped credentials, so your EBS token is never sent to S3.

## Temporary credentials for boto3

Request temporary credentials restricted to the trigger's bucket:

```sh
ebs s3 credentials data-ready
```

This command intentionally prints the access key, secret key, and session token to stdout. Keep them out of logs and shared terminals. The default lifetime is 900 seconds; choose 900 through 3600 seconds with `--duration-seconds`. These credentials are separate from your login and are not renewed automatically — just run the command again when they expire.

Each exchange is scoped to one operation. Request exactly the scope you need with `--operation`:

| Operation | Allows | Withholds |
| --- | --- | --- |
| `upload` (default) | Put objects, multipart uploads, and bucket listing | Reading or deleting objects |
| `list` | One bounded `ListObjectsV2` page | Reading, writing, deleting |
| `download` | Reading one specified object | Listing, writing, deleting |
| `delete` | Deleting one specified object | Listing, reading, writing |

The credentials never grant access to another Project's bucket.

The default output is a ready-to-run Python example for boto3. For the `upload` scope it looks like this — replace the placeholders with the returned values and adjust the local path and object key:

```python
import boto3
from botocore.config import Config

s3 = boto3.client(
    "s3",
    endpoint_url="https://s3.example.test",
    region_name="us-east-1",
    aws_access_key_id="TEMPORARY_ACCESS_KEY",
    aws_secret_access_key="TEMPORARY_SECRET_KEY",
    aws_session_token="TEMPORARY_SESSION_TOKEN",
    config=Config(
        signature_version="s3v4",
        s3={"addressing_style": "path"},
        connect_timeout=10,
        read_timeout=120,
    ),
)
s3.upload_file("./data.fits", "TRIGGER_BUCKET", "incoming/data.fits")
```

Use `--shell` for environment-variable exports instead of the Python example, or `--json` for automation — the credential output intentionally contains the secrets, so handle it carefully:

```sh
ebs s3 credentials data-ready --shell
```

## List objects

Fetch exactly one bounded page of objects:

```sh
ebs s3 ls data-ready
ebs s3 ls data-ready --prefix run/
```

The page size is 100 by default and `--limit` accepts 1 through 1000. The table shows each object key, size in bytes, and last-modified time. When the store reports another page, the output shows the continuation token — pass it to the next call as `--cursor TOKEN`; otherwise there is nothing more in this result set.

## Download an object

Stream one object to a local file:

```sh
ebs s3 download data-ready run/data.fits ./data.fits
```

An existing destination is refused unless you pass `--force`, and a destination that is a symbolic link is always refused.

## Delete one object

Remove exactly one object:

```sh
ebs s3 rm data-ready run/data.fits
```

Attached to a terminal, the command asks for confirmation before doing anything; the default answer is No. In scripts, deletion requires `--yes`; without it the command refuses. Only the exact key you name is deleted — prefixes and recursive trees never are.

## One-object upload URLs

Generate a presigned PUT URL for one object key:

```sh
ebs s3 upload-url data-ready incoming/data.fits
```

The output shows the `s3://` target, expiry, and a `curl --request PUT --upload-file` command. The signed URL is replaced with `[signed URL redacted]` by default, because anyone holding it can upload that object until it expires. When you intentionally need to run or copy the complete command, reveal it with `--show-url` — and do not send the revealed URL through chat, logs, tickets, or untrusted command history.

## Upload a local file

Upload directly to the trigger's bucket without the file passing through EBS:

```sh
ebs s3 upload data-ready ./data.fits --key incoming/run-42.fits
```

The default object key is the local file name. Keys must be relative, at most 1024 UTF-8 bytes, and cannot contain empty, `.`, or `..` path segments.

## JSON output

Most commands accept `--json` for machine-readable output on stdout. Credential JSON intentionally contains secrets; object-command JSON contains only targets, paths, page data, and status — never temporary credentials or a signed URL.
